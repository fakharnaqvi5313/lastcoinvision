# create-lcv-app

Scaffolds a LastcoinVision (LCV) dApp from a starter template that runs against a devnet out
of the box.

## Usage

```bash
npx create-lcv-app my-app --template <template>
cd my-app
npm run dev
```

Templates:

| id             | stack                    | what it does                                                  |
| -------------- | ------------------------ | -------------------------------------------------------------- |
| `dapp-evm`     | Next.js + wagmi/viem     | Connects MetaMask to LCV's EVM, displays the native balance.   |
| `dapp-cosmos`  | Next.js + CosmJS         | Connects Keplr to LCV, displays the account balance.            |
| `gov-registry` | Next.js (read-only, REST)| Looks up jurisdiction authorities and registered assets.        |
| `voting-portal`| Next.js (read-only, REST)| Looks up elections and their commit-reveal results.             |

Every generated app defaults to a local devnet (`localhost` RPC/REST/EVM ports) — see its
`.env.local` to point at a different network. `gov-registry` and `voting-portal` need no
wallet at all; `dapp-evm`/`dapp-cosmos` need MetaMask/Keplr respectively.

Flags: `--template, -t <id>` (required), `--skip-install` (scaffold only, don't run `npm
install`).

### Local devnet CORS

The generated templates call the chain's REST API directly from the browser. A devnet
generated by `scripts/genesis/init-genesis.sh` (i.e. `make devnet`) already sets
`enabled-unsafe-cors = true` in `app.toml` for exactly this reason — see the 2026-08-03 entry
in the root `DECISIONS.md`. Pointing a template at some other REST endpoint that doesn't have
CORS enabled will fail with a browser-side "Failed to fetch", not a chain-side error.

## Development

```bash
npm install
npm run dev -- <project-dir> --template <template>   # runs the CLI via tsx, unbuilt
npm run build                                          # tsup -> dist/index.js (the published bin)
npm run typecheck
```

Templates live under `templates/<id>/` and are copied as-is (with `.gitignore`/
`.env.local.example` renamed from `gitignore`/`env.local.example`, since npm drops
dotfiles with those exact names from published tarballs). `@lastcoinvision/sdk` isn't
published yet: when `create-lcv-app` detects it's running from within this monorepo (a
sibling `sdk/` directory with a `package.json`), it rewrites that dependency to an absolute
`file:` path pointing at the local built package instead of leaving the plain semver range.
